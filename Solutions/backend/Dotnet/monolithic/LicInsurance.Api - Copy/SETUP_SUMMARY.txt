## 🎯 Database Schema Summary

### Table: customer_policies
| Column | Type | Notes |
|--------|------|-------|
| customer_policy_id | INT PRIMARY KEY AUTO_INCREMENT | Unique ID |
| customer_id | INT FK | References customers table |
| policy_id | INT FK | References policies table |
| purchase_date | DATETIME | When purchased |
| expiry_date | DATETIME | When expires |
| status | VARCHAR(50) | Active/Inactive/Expired/Cancelled/Pending |
| premium_amount | DECIMAL(15,2) | Payment amount |
| payment_frequency | VARCHAR(50) | Monthly/Quarterly/Annually |
| last_payment_date | DATETIME | Last payment made |
| next_payment_due_date | DATETIME | Next payment due |
| remarks | TEXT | Notes |
| is_active | BOOLEAN | Active status |
| created_date | TIMESTAMP | Auto-created |
| modified_date | TIMESTAMP | Auto-updated |

**Indexes**: customer_id, policy_id, status, is_active, purchase_date, expiry_date  
**Constraints**: FK on customers, FK on policies, UNIQUE(customer_id, policy_id)

## 🔗 One-to-Many Relationship

```
Customer (1) ──── (Many) CustomerPolicy ──── (1) Policy

Example:
- Customer "John Doe" pays for 3 different policies
- Each has its own CustomerPolicy record
- Tracks separate purchase dates, expiry dates, payment status
```
